# suspkin Restructure-and-Prune Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shrink and restructure `src/suspkin` into fewer, clearer modules with one implementation per piece of math, without changing CLI, YAML, API or numeric behaviour.

**Architecture:** First record a behaviour lock (CLI, app API, surrogate evaluator snapshots) from the untouched code. Then move bottom-up through the dependency graph (geometry → kinematics → metrics/sweeps → optimize → surrogate → plotting/report → cli → app), one commit per task, with the lock + existing golden/unit/property tests green after each.

**Tech Stack:** Python 3.12, numpy/scipy/pandas, pydantic, typer, fastapi, optional numba/torch/optuna/pymoo; uv, ruff, mypy, pytest + hypothesis; mkdocs-material.

**Spec:** `docs/superpowers/specs/2026-11-19-refactor-design.md`

## Global Constraints

- Behaviour frozen: CLI commands/flags/defaults/exit codes/stdout/written files; YAML formats and validation errors; all 16 `/api/v1` endpoints and `frontend/src/api/openapi.json`; optional extras stay optional (`import suspkin` must work without numba, torch, optuna, plotly, pymoo, fastapi).
- Numbers: within `rtol=1e-12` (small matching `atol`) of the lock, or the existing golden tolerance (`RTOL=1e-6`, `ATOL=1e-9`) where looser. Human-readable text exact.
- Never regenerate any file under `tests/regression/golden/` or `tests/regression/behaviour/snapshots/` after Task 0. A task that can only pass by regenerating is wrong; revert the offending merge and keep the two implementations side by side with a comment.
- `examples/*.py`, `scripts/*.py` and `mkdocs build --strict` keep working after every task; update their imports and the `:::` paths in `docs/reference/*.md` in the same task that moves a module.
- Performance: `scripts/bench_kinematics.py` within ~10% of the Task 0 baseline.
- Hidden CLI alias `surrogate sample --out` is kept.
- English only; Conventional Commits `refactor(<area>): ...`; one commit per task; only the orchestrator commits. No push until the owner says yes.
- On this PC call uv as `python -m uv`.

**Gate** (referred to as "run the gate" below):

```bash
python -m uv run ruff check
python -m uv run ruff format --check
python -m uv run mypy src
python -m uv run pytest -q -m "not examples"
python -m uv run pytest -q -m examples
python -m uv run mkdocs build --strict
```

Expected: all pass, zero mypy errors. Also `grep -r "<old module path>" src tests examples scripts docs` returns nothing for every module removed in the task.

## Review Focus

- Running without numba installed (or `SUSPKIN_NO_NUMBA=1`): every command still works and gives lock-identical output. Test: Task 0 lock runs under `SUSPKIN_NO_NUMBA=1`; Task 3 adds `test_import_without_numba` (patch `importlib` so `numba` raises `ImportError`, import `suspkin.kinematics`, solve one corner).
- `import suspkin` in an env without torch/optuna/fastapi/plotly: must not import them eagerly. Test: Task 10 `test_light_import` runs `python -c "import suspkin, suspkin.cli; import sys; assert not {'torch','optuna','fastapi','plotly','pymoo'} & set(sys.modules)"` in a subprocess.
- Solver failure paths (geometry that can't close, travel out of range): the same `KinematicsError` message and CLI exit code. Test: Task 0 lock includes `sweep --travel` with an out-of-range value on `fs_reference` and records stderr + exit code.
- YAML validation errors (bad vehicle field, bad study constraint) print the same message. Test: Task 0 lock runs `summary` on `tests/fixtures` broken copies (two cases written into the lock dir) and records output.
- `optimize --resume` on an existing run folder still continues from `history.csv`. Test: Task 0 lock runs `optimize` twice (second with `--resume` and a larger `--evaluations`) and records the final files.
